## 7. 互审证据规则（2026-11-07 双向 judge 第三轮后建立）

> 触发：Bryson 把 `PROBE_URL`（主探针 L30）当成了 mihomo delay 探针的目标，**未核脚本即生造了一个"实测事实"**，并据此反驳我。

### 7.1 引用工具行为当证据 → 必须贴源
凡以「某工具/脚本/服务的行为」作为论据，**必须附脚本行号或原始输出**，禁止转述。
- ✅ `proxy_alert.sh:131` 的 delay?url= 是 generate_204
- ❌ 「delay 探针测的是 chatgpt.com」（转述，未核，错）

### 7.2 假设必须显式标注
未核实的推断，写之前先标「**假设**」，不得在下一句就当作「**实测事实**」使用。
- 本轮反例：假设"delay 目标=chatgpt.com" → 直接推出"47节点→chatgpt通是实测事实"

### 7.3 互审的覆盖边界（不能靠互审解决的问题）
**互审能抓"说出来的话"，抓不到"没说但脑子里当真的前提"。**
→ 所以 7.1 是**强制自检项**，不是"等对方来抓"。

### 7.4 事实错误必须双向对等处置
谁引用错事实都要当场标记「整条塌了」，**不因职级/归属不同而降低要求**。

### 7.5 写前机械检查清单（Bryson 2026-11-07 提议，比 7.1 可执行）

> 7.1 靠自觉（"我记得要贴源"），7.5 靠触发词（"我写没写这几个字"）。**用 7.5，7.1 作为其理由说明。**

凡句子里出现以下任一项，**必须先查一次正本，否则不许写**：

| 触发类型 | 例子 |
|---|---|
| 具体数字 | 分钟 / 小时 / 天 / 次 / $ / ¥ / % |
| 实测类措辞 | 「实测」「验证过」「实测口径」 |
| 绝对化措辞 | 「唯一」「必然」「第一」「都」「全部」「任何」 |
| **否定式绝对断言** | 「不构成」「无效」「没用」「解决不了」「不行」 |

**依据**：Bryson 一天内 6 次「推理冒充事实」，全部踩在这几类词上，一次没漏。
**有效性**：不依赖自觉，依赖"我写没写这几个字"——可自查、可互查。

**清单不完备性（2026-11-07 现场补充）**：Bryson 写「不构成**任何**采购依据」时，只漏了「任何」一个字就绕过了全部检测器 → **说明触发词清单永远可能不完备。它不是完备防线，是追加型防线：每抓到一次新变体，就补一类。**
**否定式比肯定式更危险**：听起来像谨慎，实际是同等强度的绝对断言。

### 7.6 已在别处被驳/已撤回的主张 → 不得在别处以新形式复活（2026-11-07 现场反例）

**本案反例**：根因 A（本机/代理进程段）已在 11-07 上午被论证为**定论**（B 对「9090 全绿」不构成解释，无区分力），但同日另一会话仍写成「根因初步判为 A，在做判别性验证之前不算定论」。

**机制**：一个判定被论证为定论后，**软化为"假设/初步"是错误方向**，必须显式给出反驳证据才能重开。
- ❌ 「初步判为 X，未验证前不算定论」（无新证据，只是保守措辞）
- ✅ 「X 是定论；推翻条件：出现 <具体数据>」

### 7.7 跨会话一致性（多 Agent 并行时的必检项）

**本案揭示的真实风险**：不是推理能力不足，是 **Agent 在自己的会话里，看不到该结论在别处已被升级/撤销**。
→ 凡准备向 Daryl 汇报「状态/判定/结论」前，**必须先取最新状态**（读 `memory/active.md` + 当日日记 + 相关 episode），不得只凭本会话上下文。

**成本**：一次 read ≈ 1 秒。**收益**：防止把已定论的东西说回"假设"，或把已撤回的主张说回"结论"。这比 7.5 的 grep 更重要，因为它错的是**状态**不是**事实**。

### 7.8 因果断言的"因为"必须可溯源（Bryson 2026-11-07 提议，我采纳并收紧）

**7.5 词表降级为第二道网。第一道网是"来源判据"：**

每个因果断言（「所以/因此/说明/证明」）的"因为"后面，**必须能填出 `路径:行号` 或原始输出，或明确写「我假设」**。
- 填得出源 → 可写「依据 X」
- 填不出 → **必须写「我假设」，且下一句不得用它当事实**
- **填不出却写了"所以" → 违规**

**理由（Bryson 实证）**：他的第 3 处翻车「delay 探针测的是 chatgpt.com」踩了"实测"被抓住；但如果改写成「节点侧正常，从 7892 进不去」——**一个触发词都不踩，照样是未核前提**。词表抓不到纯结构性断言。

### 7.9 7.6 的边界（防教条化）

**若后续发现"定论"本身建立在错误前提上 → 重开是纠错，不受 7.6 约束。**
否则 7.6 会退化为「我以前说过的都对」。
判据：重开时**必须指出定论所依赖的具体前提哪一条错了**，而非仅表达不安。

### 7.7 补充（2026-11-07 我本人第 7 处同型错后加）

**涉及「历史故障 / 既往判断 / 之前为什么这样」的断言，必须先 grep 对应日期的日记与 episode，不得凭本会话记忆。**

**实案**：我断言「80 轮压测零失败解释了为什么过去 3 次排查全无效——因为采样率不匹配」。核 `memory/2026-11-06.md#L90` 后发现：
> 那两次判断被推翻的原因，当天已写明——① **对 mihomo 行为想当然（认知错）** ② **抽样 5 个全失败就定性（时序错）**

→ **答案当天就写在日记里，我读了却没用，还编了个"因为采样率"。** 这不是"没写"，是"**写了但没读**"。

### 7.10 错的分类学（2026-11-07 第八轮得出）

**两类错，需要不同的防御，不能混用：**

| 类型 | 结构 | 特征 | 防御 |
|---|---|---|---|
| **I 类：前提未核** | 第一步"如果"没核，后面推理每步都顺 | 内部无矛盾，**有触发词可抓** | 7.8 因果断言须可溯源 |
| **II 类：候选集不完备** | 每个选项都分析对了，但选项本身没列全 | 内部无矛盾，**没有触发词**，比 I 类更难自察 | **强制列出第三选项**：凡出现「唯一」「只有两种」「必然」，必须反问"第三种是什么" |

**实案**：A/B 二分被当成穷尽，推出"A 是唯一相容解释"。漏了 C（节点瞬时抖动）。**这不是前提错，是选项缺。**

### 7.11 机制产出转化率（比数量更该盯的指标）

**问题不在"事后规则多还是事前规则少"，在"抓到的错有没有转成事前阻断"。**
- 今日：抓到 9 处错 → 转成事前规则 3 条（7.2/7.7/7.8）→ **转化率 33%**
- **盯这个数，不盯规则条数。**

**同时承认**：事后规则不是零价值——7.5 触发词清单本身是事后产物，但现在能在写之前提示。**"事后产出"≠"无事前价值"。**

### 7.12 规则的**作用域**限定（Bryson 2026-11-07 追问，我采纳）

**禁止说「某规则判据完备」而不限定作用域。**

| 规则 | 作用域 | 域内完备？ | 管不到的错型 |
|---|---|---|---|
| 7.8 因果溯源 | **仅因果断言**（所以/因此/说明/证明） | ✅ 完备 | **排序判断**（「X 是第一要素」）、**否定断言**（「不构成任何…」）、**存在断言**（「只有 A 和 B」）——**这三类根本不写"因为"，7.8 管不到** |

**实案**：Bryson 9 处错里，「商家政策是第一要素」是排序判断、「不构成任何采购依据」是否定断言——**两处都没有因果词，7.8 全都管不到。**

→ **正确表述："7.8 在因果断言域内判据完备。"** 我之前说"唯一判据完备的规则"是不带作用域的过度概括。

### 7.13 新错误映射到旧分类 → 会掩盖真实性质（2026-11-07 真实故障实证）

**案**：我给 `curlrc=35`（TLS 握手失败）写了映射 `→ CAUSE=C（链路/节点瞬时抖动）`。真实故障发生时（10:37，持续 >11 分钟，56 节点全挂），自动判定输出了 `CAUSE=C 瞬时抖动`——**方向对（排除 B），但标签错了两处**：
1. **35 ≠ 瞬时**：它可能是持续的上游 TLS 断连
2. **不是抖动**：实测连续 12 轮 60 秒全失败 + 56/56 节点 503/504

→ **机制：把新错误塞进旧分类，会让日志输出一个"看起来已归因"的错误标签。** 这比"未映射"更危险——**未映射至少写着"未知"。**
→ **修正原则：新错误形态先记 `CAUSE=未知(形态X)`，需在 ≥2 个独立故障事件复现同一形态才可分类。**
   （"≥3 个样本"阈值已废：同窗口 100 样本 = 1 事件，会被污染。Bryson 2026-11-07 提出，我采纳。）

**7.13 的根因不是"样本不够"，是"原定义不可反驳"：**
- ❌ `C = 瞬时抖动` —— 任何一次 curlrc=35 都能塞进去，**永不会被证伪** = 假定义
- ✅ `C = 连续失败≥N轮 且 跨≥2个独立事件` —— 10:37 那次持续 16 分钟，**"瞬时"当场被推翻** = 真定义

→ **因此 7.13 必须配上 7.14（定义须可反驳），否则改了措辞还是假定义。**

### 7.16 三刀分层（今日唯一成体系的产物）
| 刀 | 对照 | 切开什么 |
|---|---|---|
| 第一刀 | 直连 vs 走代理 | 是不是代理的锅（A vs 非A） |
| 第二刀 | 9090 API vs 7892 入口 | 代理进程活着 vs 隧道通 |
| 第三刀 | ctrl204(generate_204) vs chatgpt | 隧道通 vs 目标站处置出口IP |

**三刀切完只剩一种可能。** 注：Bryson 坦白第二刀是"先做了才明白它是对照"，非先设计——**方向对但过程靠运气，说明对照意识尚未内建。**

### 7.14 定义必须「可被证据反驳」，抄得出定义 ≠ 定义正确（2026-11-07 真实故障反例）

**Bryson 提议**：写分类标签前必须抄一遍定义原文，抄不出=禁用。
**我驳回，理由有实案**：

**我脚本里的 `C = 链路/节点瞬时抖动` 定义原文就写在注释里——我抄得出来，但那是错的定义。**
- ❌ `C = 瞬时抖动` —— **不可反驳**：任何一次 curlrc=35 都能塞进去，永不会被证伪
- ✅ `C = 连续失败轮数 ≥N 且跨 ≥2 个独立故障事件` —— **可反驳**：10:37 那次持续 16 分钟，"瞬时"当场被推翻

→ **抄得出定义只能防"遗忘"，防不了"记得错"。**
→ **规则：任何分类标签的定义必须包含「什么情况下它不成立」。写不出否定条件的定义 = 该标签禁用。**

### 7.15 对照探针的**分层极限**（同日实证）

**直连对照只能切出「A vs 非 A」，切不开 A 内部。**

| 对照 | 变量隔离 | 能判 | **判不了** |
|---|---|---|---|
| 直连 vs 走代理 | 只差"代理" | 是不是代理的锅 | — |
| 代理内部 | — | — | **进程活着 vs 隧道通了的区别** |

**实案**：`direct=204` 成立后，仍有两种分不开：①上游节点挂了 ②本机 mihomo 隧道没建起来。**处置完全不同**（前者等服务商，后者重启 mihomo）。要分开必须再加第三刀：**9090 API 逐节点延迟测试**。

→ **规则：加一个对照，只能排除一层变量。声称"排除 A"前必须说清切开了几层、还剩几层。**

### 7.17 转述压缩失真（Bryson 2026-11-07 反向观察，我采纳并落地）

**发现**：一次互审中我纠正 Bryson 的 3 处（三刀归属 / 20min vs 16min / proxy.enabled=false），**全部不是技术错误，而是"向 Daryl 转述时的信息污染"。**

| 技术判断错 | 转述压缩失真 |
|---|---|
| 今天两人盯得很紧 | **几乎没人盯** |
| 双方都能复核 | **Daryl 只看得到转述后的版本** |

→ **后者更危险：错误发生在"唯一出口"上。**

**三类转述失真（今日全部实证）**
1. **来源合并**：把"设计 / 实现 / 误用后发现"三种来源写成"我们建了" → 导致对方以为可复制
2. **跨源时间拼合**：拿自己日志首条(10:32) + 另一路恢复时刻(10:53) 算时长，对外应报**可证实窗口**(10:37→10:53=16min)
3. **解决不存在的问题**：未先确认前提（`proxy.enabled=false`）就设计并上报方案
