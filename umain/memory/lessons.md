# lessons.md — 经验教训精华

## 2026-10-30 · 检测口径必须随调度时间一起改
- **教训**: audit.sh 成本新鲜度用 60 分钟阈值，但数据源是**日更**（Balance 23:45 写一次），归档 cron 从 23:59 挪到 09:45 后必然误报「过期」。规则没改，只改了时间表 → 假阳性每天出现，久了就会让人忽略真实告警（告警疲劳）。
- **整改**: 阈值对齐数据源的真实更新周期（26h 日更容差）；**改调度时间时，同步检查所有依赖「距今多久」的判定逻辑**；报错文案要写清「过期=哪个上游漏跑」，便于定位而非只报「过期」。
