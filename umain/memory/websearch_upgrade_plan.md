## 一、问题诊断

### 1.1 技术层问题（方案C要解决的）

| 问题 | 表现 | 根因 |
|------|------|------|
| 中文搜索差 | SEO农场、百科污染、过时内容排前面 | SearXNG中文引擎质量差，无时效性权重 |
| 结果排序烂 | 付费墙Medium + 2022年博客 > Cloudflare官方文档 | SearXNG缺乏域名权重和时效性排序 |
| 专业数据覆盖不足 | 金融法规/政策文件搜不到 | 两个引擎对政府网站、专业数据库覆盖弱 |
| 引擎未分层使用 | Brave仅用于web_fetch，主力web_search仍是SearXNG | 未按查询类型智能路由 |

### 1.2 行为层问题（基建侧要解决的）

| Agent | 本周搜索次数 | 问题 |
|-------|------------|------|
| **xiaofeng** | 5-8次 | 正常，技术开发天然需要搜索 |
| **Balance** | 0-2次 | 财务分析任务(法规/汇率/SOP)本应大量搜索，却几乎不用 |
| **Self** | 0次 | 方法论卡片、知识库研究任务本应搜索，完全没搜 |

**根因**：search_methodology.md 作为被动建议存在（"when doing web searches, follow this"），而非强制执行规则。Agent的AGENTS.md中没有「必须搜索」条款——搜索被当作「可选动作」而非「默认动作」。

**恶性循环**：
```
搜索质量差 → 搜了也没用 → 不搜 → 搜索技能退化
           → 没有反馈数据 → 不知道哪里差 → 没法优化 → 质量继续差
```

## 二、基建侧更新：Agent 搜索强制条款

### 2.1 核心原则

> **信息依赖型任务（Information-Dependent Task）必须执行至少1轮websearch，作为完成任务的基本动作之一。**

### 2.2 任务分类 → 搜索要求

| 任务类型 | 定义 | 最小搜索轮次 | 示例 |
|----------|------|------------|------|
| **🟢 纯逻辑推理** | 仅涉及已知事实/逻辑推导 | 0轮，不需要 | 数学计算、代码审查、已知规则判断 |
| **🟡 信息依赖性·轻** | 涉及通用知识或可推断信息 | 0-1轮，建议搜 | 最佳实践确认、通用技术问题 |
| **🔴 信息依赖性·重** | 涉及外部事实/时效性数据/专业领域 | **≥1轮，强制搜索** | 政策法规、市场数据、学术研究、行业标准、第三方工具文档 |
| **🔴 外部交叉验证** | 涉及不确定事实或需要多方确认 | **≥2轮，强制双搜** | 法规解读、数据口径对齐、跨源对比 |

### 2.3 各Agent搜索强制场景

#### Self（恨点小己）— 知识管理/深度研究
**强制搜索场景**：
- 🔴 方法论卡片编写 → 必须搜索该领域已有框架/学术文献/同行研究
- 🔴 跨域分析 → 必须搜索每个域的权威定义和最新动态
- 🔴 ACCA知识库架构 → 必须搜索行业最佳实践对比
- 🔴 Daryl提出的任何「帮我查一下/分析一下」类问题 → 必须搜索
- 🟡 内部知识索引/检索 → 建议搜（可仅查内部知识库）

#### Balance（算点小账）— 财务分析
**强制搜索场景**：
- 🔴 法规/政策解读 → 必须搜索官方原文（site:gov.vn / site:sbv.gov.vn）
- 🔴 汇率/利率/市场数据 → 必须搜索最新数据源
- 🔴 会计/税务准则 → 必须搜索权威来源
- 🔴 SOP编制 → 必须搜索行业标准操作流程
- 🔴 财务分析报告 → 必须搜索可比案例/市场基准
- 🟡 内部台账整理 → 建议搜（可仅查内部数据）

#### xiaofeng（吹点小风）— 技术开发
**强制搜索场景**：
- 🔴 API/库/框架文档 → 必须搜索官方文档（当前已在做）
- 🔴 Bug修复/Error排查 → 必须搜索（当前已在做）
- 🔴 架构模式/最佳实践 → 必须搜索对比方案
- 🔴 第三方服务配置（Cloudflare等） → 必须搜索最新文档
- 🟡 已有知识复现 → 建议搜（可仅查内部文档）

#### main（忧郁小猫）— 总协调/项目执行
**强制搜索场景**：
- 🔴 Daryl委派的调研任务 → 必须多轮搜索
- 🔴 技术选型/方案对比 → 必须搜索
- 🔴 外部工具/服务评估 → 必须搜索
- 🔴 其他Agent搜索质量存疑时 → 必须交叉验证

### 2.4 搜索执行检查清单（写入所有Agent AGENTS.md）

收到用户任务后，Agent必须自问以下3个问题：

```
□ 这个任务是否需要外部信息来保证答案的准确性和全面性？
  YES → 至少1轮websearch
  NO  → 标注「纯逻辑推理任务，未使用websearch」

□ 我是不是只依赖了自己的预训练知识？
  YES → 警告标记，说明你该搜索了
  
□ 任务涉及的数据/法规/标准有时效性吗？
  YES → 必须搜索确认最新版本，不可凭记忆
```

## 三、技术侧升级：方案C 混合智能路由

### 3.1 搜索引擎分层策略

```
                    ┌─────────────────────┐
                    │   搜索请求          │
                    └────────┬────────────┘
                             │
                    ┌────────▼────────────┐
                    │  查询类型分类器     │
                    └────────┬────────────┘
                             │
          ┌──────────────────┼──────────────────┐
          │                  │                  │
   ┌──────▼──────┐   ┌──────▼──────┐   ┌──────▼──────┐
   │ SearXNG     │   │ Brave API   │   │ 混合双搜   │
   │ (精简引擎)  │   │ (web_search)│   │ SearX+Brav  │
   │             │   │             │   │ 交叉验证    │
   └──────┬──────┘   └──────┬──────┘   └──────┬──────┘
          │                  │                  │
          │          ┌───────▼───────┐          │
          │          │  web_fetch     │          │
          │          │  深度内容提取  │          │
          │          └───────┬───────┘          │
          │                  │                  │
          └──────────────────┼──────────────────┘
                             │
                    ┌────────▼────────────┐
                    │  结果合并+去重      │
                    │  黑白名单过滤       │
                    │  时效性加权         │
                    └────────┬────────────┘
                             │
                    ┌────────▼────────────┐
                    │  最终结果输出       │
                    └─────────────────────┘
```

### 3.2 查询路由规则

| 查询类型 | 引擎策略 | 参数 | 场景 |
|----------|----------|------|------|
| 🔵 英文技术 | Brave API → web_fetch 深度提取 | language=en | 编程、API、框架、工具文档 |
| 🟢 中文内容分析 | SearXNG + 黑名单过滤 | language=zh-CN, categories=general | 影评、文学分析、知乎/豆瓣 |
| 🟡 金融/政策法规 | Brave API(en) → 无结果→SearXNG+site:限定 | language=en + site:gov/sbv等 | 法规原文、汇率政策、会计准则 |
| 🟠 越南本地信息 | SearXNG | language=vi | 本地新闻、特产、行政信息 |
| 🔴 关键决策依赖 | SearXNG + Brave 双搜交叉验证 | 两个引擎各自搜，结果合并 | 架构选型、法律合规、数据口径 |

### 3.3 SearXNG 引擎精简

**当前**：多个引擎混杂，包括低质量引擎

**精简后**（仅保留4个高质量引擎）：
```
- google (general)      # 通用搜索最强
- duckduckgo (general)  # 隐私搜索引擎，补充结果
- brave (general)       # Brave索引，英文技术好
- bing (general)        # 微软引擎，中文相对好
```

移除：低质聚合站引擎、结果重复率高的引擎、性能差的引擎

### 3.4 搜索结果后处理规则

#### 黑名单自动过滤（追加新条目）
在现有基础上增加：
| 新增黑名单 | 原因 |
|-----------|------|
| vi.wikipedia.org | 百科类无分析价值（当前已触发但未在规则中） |
| medium.com (paywall) | 付费墙文章，无法获取完整内容 |
| 360doc.com | 洗稿低质站 |
| m.fx361.com | 中文转载农场 |

#### 时效性加权
```
发布时间 < 1年: +3
发布时间 < 2年: +1
发布时间 > 5年或无日期: -2
```

### 3.5 场景化搜索模板（6种）

#### 1. 技术文档搜索
```
模板: [精确关键词] [版本号/年份] site:[官方域名] 
示例: "Cloudflare Tunnel" "API configuration" site:developers.cloudflare.com
降级: 去掉site限定 → 加 "tutorial" / "guide" → 换引擎
```

#### 2. 政策法规搜索
```
模板: [法规编号/名称] [年份] site:[gov域名]
示例: "Circular 12/2022/TT-NHNN" "foreign borrowing" site:sbv.gov.vn
降级: site:thuvienphapluat.vn → 英文名搜Brave → 直接访问官网
```

#### 3. 创意/人文分析搜索
```
模板: [作品名] [分析维度] [平台限定]
示例: "寄生虫" "空间隐喻" "电影分析" site:zhihu.com
降级: 去平台限定 → 英译 → Douban/IMDB
```

#### 4. 金融数据搜索
```
模板: [指标英文名] [时间范围] [source限定]
示例: "USD/VND exchange rate" "July 2026" "SBV"
降级: 去source限定 → 切换越南语 → 直接访问官网
```

#### 5. 通用百科/生活搜索
```
模板: [核心问题] -百科 -广告 -推广
示例: "如何选择咖啡豆" -baike -tmall -jd.com
降级: 简化到核心词 → 英文搜
```

#### 6. 本地/越南信息搜索
```
模板: [关键词 vi] [地点限定]
示例: "làng nghề truyền thống" "Hà Nội"
降级: 英文搜 → Google Maps → 本地论坛
```
