- 取证：`git ls-remote origin HEAD` 5 次耗时 3.28~5.06s（无 GIT proxy 的 GitHub SSH 本来就慢）

- 修改 `scripts/compliance/audit.sh`：pull 加 **3 次重试 + 错误分类**
  - 网络类错误（Could not read from remote / timed out / Connection）→ 重试 3 次，仍失败降级为 `log_warn`（非真断链，交由 push 链路独立校验）
  - 非网络类错误（真分歧/冲突）→ 立即 `log_issue`，不重试
- 验证：`bash -n` 语法通过；实跑 pull 成功，全项转绿

### 教训
**告警分级比告警本身重要。** 之前 pull 抖动和真断链共用一个 `log_issue`，导致这条「假红」长期挂在审计里，反而稀释了真问题的信号强度 —— 出现多了就没人看。
