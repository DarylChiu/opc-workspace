### 四个新踩的坑（重要，路由器上会直接失败）
1. **`respect-rules: true` 造成订阅自举死锁** — 订阅域名被规则判进 PROXY，但代理还没起来 → 永远拉不到订阅。必须 `false` + 首行加订阅域名 DIRECT
2. **节点域名只有微风私有 DNS `43.108.56.44` 能解析** — 阿里/腾讯/114/Google DNS 全部失败。`proxy-server-nameserver` 只能写这一个，加公共 DNS 会先返 NXDOMAIN 导致失败
3. **mihomo 内置拉取这个订阅报 EOF，curl 正常** — 同 URL 同时刻。provider 自动更新不可靠，改脚本拉取
4. **原订阅 DNS 顺序导致冷启动全超时** — DoH/TLS 排前面，永远轮不到纯 UDP

### 教训
1. **「验证机制」和「交付生产」是两件事** — 我之前拿验证 provider 机制的测试配置当交付物给 Bryson 审，规则段只有一行兜底。这种配置一旦上了路由器，国内流量全部绕道海外。**测试配置必须显式标记「仅测试」，不能当交付物**
2. **同机并行测试缺协调** — 我和 Bryson 都起了 mihomo 实例，两次端口冲突（`bind: address already in use`），我一度查到旧进程数据白排查两轮。**以后并行测试先报备端口**
3. **异地验证 ≠ 本机验证** — 坑2/坑3 只有真机端到端才撞得到，纸面审查抓不出来
4. **Bryson 三轮审查每轮都有真发现** — 互审机制确实在防止方案出错浪费钱，值得固化成流程

### 排障过程中的关键发现（重要）

**假故障1 · 55% 丢包**：插网线瞬间 DHCP 切换导致，稳定后 0%。

**假故障2 · 55 个节点全部"不可达"**：实测是 **DNS 轮询 + mihomo 缓存旧 IP**。
- 微风私有 DNS `43.108.56.44` 返回的 IP **会变**：`47.243.157.61` → `47.239.101.61`
- mihomo 缓存了旧 IP → 连不上；但手工 `socket.create_connection` 到新 IP 是通的
- **重启 mihomo 让其重新解析即可** — 这是个隐蔽的坑，路由器长期跑会遇到

**假故障3 · 固定美国节点全部失败**：`🇺🇸 美国 01` 固定后 5/5 失败，切回 `AUTO` 组 10/10 成功。
**不要手工固定单一节点，让 url-test 自动选。**

### 🔍 重复的真正根因（我挖出来的）
- 514 组重复，**全部同文件内，零跨文件**
- 样本：同文件 `6da43019-...jsonl`，line9 (03:43) 与 line221 (06:18) responseId **完全相同**，cost 都是 0.005884884
- 中间 line218 = **compaction 事件**（`firstKeptEntryId=9e87ee3c`）

- 重放时 record `id` 变了（`da72bb88` → `bcba07e6`），**只有 `responseId` 不变**
- **结论：`responseId` 是唯一可靠去重键，用 `id` 去重必漏**

### 11-03 差异真相：不是分歧，是快照时间不同

### 我在这个问题上犯了两次错
