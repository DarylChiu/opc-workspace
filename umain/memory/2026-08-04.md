## OPC自进化基建L1 · M0+M1 交付 (16:30)

### 背景
Daryl回国度假暴露核心问题：管理者不在→系统停摆。指令推进自进化/Loop Engineering/自主任务基建，核心原则"时间成本>API成本，停工=亏损"。

### 关键设计决策（多轮讨论）
1. **教训形成**: 事件驱动捕获（Daryl纠错/任务失败/审计违规/复盘），非Agent自觉写反思——修复"lesson文件<1周1次、<30行"的现状
2. **检索架构**: 结构化JSON真相源 + trigger字段 + 规则表(确定性) + embedding语义层(兜底)——纯向量库否决（规模不匹配+不可解释）
3. **注入时机**: 任务边界（M2），非session边界——天气闲聊不注入，前端开发任务注入设计语言教训
4. **混合向量**: 写入时算embedding存JSON，查询时本地numpy余弦，零API成本

### 交付物
- scripts/evolution/: capture_correction.sh, distill_patterns.py, distill_weekly.sh, embed_patterns.py, retrieve_patterns.py, test_evolution.sh, launchd plist
- memory/evolution/: failure_patterns.json(4模式), rules_table.json(4规则), corrections_inbox.jsonl
- AGENTS.md: 信号捕获条款（4Agent共享）
- commit 7bf03311 | 回归测试4/4通过

### 技术要点
- DeepSeek API model名不带deepseek/前缀（deepseek-v4-pro直接可用）
- 中文检索分词：2-gram方案（无分词依赖）
- crontab写入被macOS权限阻塞→改用launchd（周日22:00蒸馏）
- 蒸馏三条件过滤：3信号→2模式+1丢弃（LLM自动判断）

### 经验
- 教训库=事件驱动捕获+自动化蒸馏，不是"要求Agent多写"
- 设计顺序错误教训：先设计"库从哪来"再设计"怎么检索"
