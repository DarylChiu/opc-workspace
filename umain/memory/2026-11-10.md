### 教训
- **监控本身也会腐烂**：路径迁移后忘了同步 crontab，看门狗表面存在、实际永久失效。凡是「守护脚本指向绝对路径」，迁移目录时必须同步改，且要看门狗报告自身失败。
- **「API 200」≠「功能在」**：之前 watchdog 的判定是 `cost_api_ok=0` 逻辑，服务活着但成本数据缺失也会被误判为健康。数据契约（是否含金额字段）应纳入健康检查。
- **rsync 软链陷阱（已实测复现 2026-11-10）**：真正致命点不是 `--delete`（我先前误判，已认错）。真实机制：**源端条目是软链、目标端同路径是非空实体目录** → `rsync -a` 试图用软链替换实体目录，遇非空则 `unlinkat: Directory not empty`，exit 23。无需 `--delete` 即可触发。
  - `--no-links` → `skipping non-regular file` + exit 0，干净跳过且保留实体（**推荐**，原生优于自制检测）
  - `--keep-dirlinks/-K` → 无效，方向相反（那是目标软链穿目录）
  - 最小复现：`/tmp/rsynctest`（已清理）
  - **通用教训：未复现前不要把机制归因到某个具体 flag 上。** 本轮我先归因 `--delete`，被 Self 实测推翻。
