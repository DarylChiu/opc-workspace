- **核心结论**：3 个月项目能否成，决定性因素不是模型聪明/更多 skill，而是 **harness**（规划+记忆+纠偏基础设施）。依据：arXiv《The Horizon Gap》2608.06663；emergentmind 长时域规划综述
- **两个机制**：北极星+分层拆解(DAG) / 里程碑门禁+重规划循环 / 持久记忆(跨 session，#1 缺口) / 纠偏=检测漂移+上报+提议 / 方向选择=人定北极星+agent 给选项（LLM 天生不擅长自己定方向）
- **关键区分（Daryl 自己提出的硬问题）**：工程型=目标已知（分解+执行+验证，纠偏=例外）vs 探索型=目标未知（假设+验证+修订，纠偏=核心循环）。OPC 创业属后者，**不能拆里程碑-子目标-任务，要拆「命颖+假设清单+最小验证」**（参考 McGrath 发现驱动规划）
- **交付瓶颈根因（Daryl 点出）**：「完成的定义」只在他脑子里，没落进 Agent 工作流 → Balance 交 V1 就停，不知道不够。正解：**spec 前置 + 自检迭代 + 独立 verifier**
  - 参考：`github/spec-kit`（Specify→Plan→Tasks→Implement→Converge）、`addyosmani/agent-skills` 的 definition-of-done.md、dev.to「独立只读 verifier agent 验证 done」
  - Token 成本：spec 写一次很便宜，但省掉 4-5 次迭代（每次要重读上下文+重生全文）→ **净省一半以上**，把迭代压到 2-3 版
  - **发起人填不完 spec 时的分类器**：发起人不需要准确填，**Agent 起草 + 发起人批改**（批改比原创省一个量级）；连批改都做不到 → 是探索型任务，改用假设验证
