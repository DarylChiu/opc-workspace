# 教训：推荐外部付费服务前必须核验核心功能（2026-11-01）

## 事件
为 Daryl 推荐翻墙机场时，只核验了：域名可达性、价格、流量额度、是否"全 IPLC 不限设备"。
**没有核验**：是否仍支持第三方客户端订阅。

结果：Daryl 买了微风网络 ¥25/月，装好才发现后台公告明写「暂时关闭原有订阅链接按钮，暂时不支持第三方客户端」，¥25 有损失风险。

## 根因
把「网站能打开 + 价格合适」当成了「服务可用」。
实际上机场这类服务最高频的失效点恰恰是**功能收缩**（下线订阅、限制设备数、砍节点），而不是网站打不开。

## 机制（以后永久执行）

### 推荐任何外部付费服务前的核验清单
1. **目标功能是否还在售**（不是"有这个东西"，是"现在还能用"）
2. **有无近期下线/收缩公告**（首页、公告栏、TG 频道、工单回复）
3. **用户评价里的最新抱怨**（搜 "机场名 + 跑路/限速/关闭/不能用"）
4. **是否有锁死风险**（是否强制自家客户端、是否支持标准协议）
5. 以上 4 项核验完毕，才允许给用户报价和链接

### 判定红线
- 「核心功能是否可用」= 支付前的**阻塞性问题**，不能事后发现
- 功能收缩 = 跑路前兆，比网站打不开更应该回避

### 差异维度声明
本次违反的维度：**信息时效性** —— 我用的是"网站结构正常"这类间接信号，替代了"功能可用"这个直接信号。间接信号在服务收缩期会给出假阳性。
