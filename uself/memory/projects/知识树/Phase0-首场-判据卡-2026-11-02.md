## 卡 1 · 进口单据链（原编号 #3）

**① 是什么 / 不是什么**

- 不是「六张纸齐了进口就成立」。
- 进口是**两条平行链**：
  - **物权链**（定成立与否）：销售确认/订单或合同 → 形式发票或商业发票 → 装箱单 → 报关单 → 提单
  - **成本构成链**（定金额多少）：缴款书、运费单
- 单据功能（Daryl 现场口径）：
  | 单据 | 功能 |
  |---|---|
  | 销售确认 / 销售订单或合同 | 确定**买卖关系**（先于单据存在） |
  | 形式发票 PI / 商业发票 CI | 确定**收款义务** |
  | 装箱单 | 卖方**物权转移给物流**的证据 |
  | 报关单（通关） | 海关对**物权转移的外部佐证** |
  | 提单 B/L | **控制权**从进口海关转移到买方 |
  | 缴款书、运费单 | **不在物权链上**，只确认进口业务**完成性与真实性** |
- **对 N2 清单的修正**：N2 写的「进口六单据链（发票/装箱/提单/报关/缴款书/运费）」两项错误——① 把缴款书、运费单算进物权链；② 漏掉销售合同/订单这一**先决**单据。以本卡为准。

**② 人会怎么错 / AI 会怎么错**

- **人的错法**：不知道单据的**发生逻辑**。典型：货还没到岸就索要提单（提单本应装船后签发，到港前就该存在；真正会缺的是报关单，因为要等你申报）。
- **AI 的错法（Self 现场实录 4 条，非推测）**：
  1. **把 Incoterms 当科目对照表** → 误写「CIF→151、DAP→152」。科目由**用途**决定（原料 152 / 转售商品 156），Incoterms 只决定 `151` **停留多久**。
  2. **用清单代替因果链** → 给出「六单据完整性 checklist 逐项打勾」，不知顺序不可逆。
  3. **只取两个极端当例子** → 只举 CIF、DAP，漏掉 FCA/EXW（151 停留最久）与 DDP（几乎不出现 151）。
  4. **概念滑动** → 把「运费能否拆开」说成「科目不同」。真差别在**可否单独计量**：FOB/CFR 有独立运费发票（可归属、需分摊）；CIF/DAP 已含在货价里（拆不出）。
- **根规律（本条为卡 1 的核心产出）**：
  > AI 的错不是答错，是**答得太整齐**。它会输出一张左右对称的映射表，看着专业可信，错的恰恰是表的形态——**真实业务是非对称的**。人的经验是碎的、带例外的，所以不会被对称表骗。

**③ 证据标准**（看到什么就算成立）

- 风险转移点（Incoterms）→ 定 151 停留时长；**用途** → 定落地科目（152/156）。
- 运费：有**独立运费发票**才算可单独归属、需分摊。
- 关税完税价格：DAP 货价含越南境内段运费，**进口后段要剔除**（此条待与报关行核）。

**④ 口径来源**

- **C 级（实务一致）**——Incoterms 风险点作会计触发点，VAS **无明文**。
- 待核：`TT 200/2014` 是否已被新通函替换（会后查，不现场检索）。
