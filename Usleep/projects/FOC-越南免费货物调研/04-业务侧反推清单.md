# FOC-VN · 业务侧反推清单（合同 · 单据 · 审批流）

- 建立日期：2026-10-07｜作者：Self
- **建立缘由（Daryl 原话）**：
  > 「H2 纳入质量责任赔付/无偿赠送这两类——基于我在目前的单据流（包括合同）上没有发现有质量责任赔付的详细条款，只有个框架条款，**我们这次的 FOC 深度调研不单是规范财务部的账务和税务处理，还需要反推到业务部去规范他们签订合同，增加 FOC 需要的单据和审批流**」
- **结论**：本项目从「单轨（财务）」扩为**双轨**：**财务侧规范**（账务＋税务）＋ **业务侧规范**（合同＋单据＋审批流）。**两轨不是并列，是因果**——见 §1。

---

## 1. 为什么必须反推到业务部（财务侧无法单独成立）

```
合同里有没有「质量责任条款」
        │
        ├─ 有（且可举证）→ H2 定性＝履行合同质量义务 → 赔付/保修路径
        │                   → 费用性质清楚 + CIT 扣除证据链完整
        │
        └─ 没有（现状：只有框架条款）
              → H2 只能按「无偿赠送」处理
              → VAT：按同类/等价商品计税价计销项（不能主张 0）
              → CIT：扣除依赖费用性质的说明力，稽查风险高
              → 且「不回收旧件」缺少合同依据 → 无法解释为何不退货
```

> **一句话**：**合同的条款质量，直接决定财务的处理路径和风险等级。**
> 财务不能自己造依据——所以**必须反推业务部**。这也是本项目从"账务税务合规"升级为"业务—财务一体化规范"的根本原因。

## 2. 合同侧要求（建议条款要点）

### 2.1 H2 客诉免费补货 · 需补充的条款

| # | 条款 | 要点 | 为什么需要 |
|:--|:---|:---|:---|
| C1 | **质量标准与责任界定** | 明确不良判定标准、责任归属（生产方/QA 漏检）、举证方式 | 没有它，「质量责任赔付」定性无从成立 |
| C2 | **赔付方式** | 明确可选：免费补货 / 折价 / 退货退款，及**补货是否需回收旧件** | 决定是否存在退货链与调整发票 |
| C3 | **不回收旧件的约定** ⭐ | 明确「**补货后旧件不退回，由买方自行处置**」及其理由（运费成本） | 现状是实务惯例、无合同依据；一旦被稽核，无法解释为何不走退货 |
| C4 | **质量条证据清单** | 约定以「客诉记录 + QA 检验报告 + 不良率数据」为认定依据 | 把稽查时要的单据**前置进合同** |
| C5 | **税务与发票安排** | 明确双方对 VAT/票据的配合义务（如买方须出具收货确认） | 0% 与计税价问题需要对方配合 |
| C6 | **时效** | 明确质量责任期（是否等同保修期）与客诉提出时效 | 决定「是否在保」，影响定性 |
| C7 | **赔付额度与审批挂钩** | 约定超过某金额需书面确认 | 与内部审批流对齐（§4） |

### 2.2 H1 开发阶段样品 · 需补充的条款

| # | 条款 | 要点 |
|:--|:---|:---|
| S1 | **样品性质** | 明确「**无偿提供、非销售**」；数量（5–10 码）、用途（开发打样） |
| S2 | **所有权与处置** | 样品交付后所有权转移？可否转售/销毁？ |
| S3 | **报关与运输责任** | ⭐ 明确**由谁负责报关**、承运方式、**承运人申报凭证由谁提供** |
| S4 | **税务承担** | 双方对样品 VAT 的承担与配合（对方是否出收货确认） |
| S5 | **知识产权与保密** | 花型/工艺保密（面料厂刚需） |
| S6 | **后续订单关系** | ⚠️ 现状：**与订单无勾稽**。若未来要支持"损耗吸收"，需约定勾稽机制；**本期 Daryl 已决定费用化计入研发费用，不做资本化** → 本条列为**可选、暂不推进** |

## 3. 单据侧要求（必备清单 · 责任部门 · 时点）

> **设计原则（本条最关键）**：**FOC 性质必须在"源头单据"上标注**。
> 若出库单上不写「FOC / 免费」，财务无法识别、无法归集、也无法与订单勾稽——**这是现状最大的单据缺口。**

| # | 单据 | 责任部门 | 时点 | 用途 | 现状 |
|:--|:---|:---|:---|:---|:---|
| D1 | **FOC 申请审批单**（送样 / 赔付各一版） | 业务发起 | 出库前 | 证明无偿性质 + 审批留痕 | ❓待建 |
| D2 | 客诉记录（含客户主张与时间） | 销售/客服 | 客诉发生时 | 质量责任赔付的起点证据 | 有 |
| D3 | **QA 检验报告 + 不良率数据** | QA | 检验时 | 责任归属与金额依据 | 有 |
| D4 | **补货 / 送样出库单（须标注 FOC 性质）** | 仓库 | 出库时 | 存货减少与费用归集入口 | 有（**未标 FOC**）⭐ |
| D5 | 补货/送样决定与审批记录 | 销售负责人 / 财务 | 出库前 | 审批流留痕 | ❓待建 |
| D6 | **对方签收确认** | 销售（向客户索取） | 交付后 | 交付完成的证明 | ❓待建 ⭐ |
| D7 | **报关凭证（MEC／H21 报关单副本）** | 物流/关务（**向 DHL/FedEx 索取**） | 发货后 | VAT 0% 条件之 (c)；海关稽查轨 | ❓未索取 ⭐ |
| D8 | 快递面单 / 运单 | 物流 | 发货时 | 实物出境的痕迹证据 | 有 |
| D9 | 发票（0 价电子发票 / 按市价计税的发票） | 财务 | 出库同期 | **样品/赠送类必须开票** | ❓待确认 |
| D10 | **样品台账 / 客诉赔付台账** | 财务＋业务 | 持续 | 汇算与稽查应对 | ❓待建 |

> ⭐ = 现状缺失或未做法，属**本次反推的重点**。

## 4. 审批流建议（谁批 · 额度 · 留痕）

```
H1 送样（开发阶段）
  业务/研发提样 ──► 部门负责人批（额度内）──► 仓库出库（单据标 FOC）
                  └─► 超额度 → 研发/销售总监批 ──► 财务备案

H2 客诉赔付
  客诉登记（销售）──► QA 确认责任与不良率 ──► 销售负责人批（额度内）
                                              ├─► 超额度 → 总经理批 ──► 财务复核
                                              └─► 仓库出库（单据标 FOC）──► 财务开票 + 台账
```

**待 Daryl 定的三个参数**：
1. **额度阈值**（分级审批的金额线）
2. **审批层级**（谁有最终签字权）
3. **财务介入时点**（事前复核 还是 事后备案）

> ⚠️ 审批流的核心不是"多一道签字"，是**在源头把 FOC 的性质、金额、责任固定下来**——这样财务侧的分类、计税价、扣除证据才有出处。
