# 深度分析：Codex/Claude Code 基建背后的第一性原理 + OpenClaw 缺口

> 2026-10-05 · Kitty · 承接上一份调研，本轮只讲"为什么"和"我们缺什么"，不讲"他们有什么"。

## 一、把基建还原成三个不可压缩的问题

Codex 和 Claude Code 的所有基建，本质都在回答三个问题：

1. **上下文预算**：每个会话从零开始、窗口有限 → 决定"把什么加载进窗口"。
2. **信任边界**：agent 能自主到什么程度 → 决定"哪里画边界，让 agent 在边界内自由工作"。
3. **能力积累**：怎么让 agent 不重复犯同样的错 → 决定"经验如何变成能力"。

我们（24/7 多通道网关）和他们（单项目 coding CLI）在这三个问题上的权重完全不同：
- 问题 2 我们更重——常年无人值守、4 个 agent、跨通道，信任边界是命门。
- 问题 3 我们最弱——他们有 Auto Dream 巩固，我们只有"人工更新 lessons.md"。
- 问题 1 我们暂时最轻——1M 上下文，现在只用 5%，但"加载什么"的纪律决定了长期是否会爆。

## 二、记忆的深层洞察

### 1. 他们的记忆是"加载优先"，不是"查询优先"
MEMORY.md 索引 + 主题文件 + grep，召回靠"读索引全文 + grep"，**不用向量**。原因不是向量不好，而是：单项目场景下，一个精炼的 ≤200 行索引 + grep 足够，且确定性强、可 debug、可 git 版本化、零 embedding 成本。

**但我们不能照抄**。我们的记忆空间比他们大一个数量级且异构（4 agent、几十项目、每日日志、episodes）。向量正是为"跨海量异构文档找针"设计的——所以我们的 memory_search 不是错的。我们真正缺的不是"向量 vs grep"的二选一，而是**缺一个精炼的、始终加载的索引层**：我们的 MEMORY.md 只放指令、手工维护，没有把 episodic 记忆压缩进去的"200 行等效物"。

### 2. 巩固 = 有损压缩，三个约束我们一个都没满足
Dreams/Memories 本质是把 N 个会话**有损压缩**进一个有界记忆库。它有三个关键设计约束：
- **异步**：需要空闲 + 整库输入（不打断前台任务）
- **非破坏**：输入库不变，输出是新的、可丢弃的
- **可审阅**：人能看 diff 再决定

对照我们：23:59 cron + heartbeat 做的是"验证文件在不在/新不新鲜"，是**验证**，不是**语义压缩**。三个约束一个都没满足。这是最硬的缺口。

### 3. 巩固的价值在"遗忘"，不在"记住更多"
Dreams 的核心操作是去重、替换过期/矛盾、删除 stale。我们的记忆系统是**只增不减**的，长期必然退化成噪声。这是"自进化"真正的引擎所在——不是记住更多，而是忘掉该忘的。

## 三、自进化的深层洞察

### 1. 真正的自动闭环只有"巩固"一个
其余（skills/subagents/hooks）都是"人搭好轨道，agent 在上面跑"。不要被"自进化"这个词骗了——没人真的让 agent 改自己代码，那正是我们的红线（7/21 GEPA 叫停）。

### 2. 经验→能力 的闭环是 lesson→skill
SKILL.md 是"行为即数据"原语：把程序性知识（指令+脚本+子工具）打包成可加载产物。我们的 learning_*.md 是**只写不读**的被动文档——research_agent_self_evolution_v2.md 里我们自己就 flag 过：reflexion journal 有写无检索。闭环应该是：失败/教训 → 蒸馏成 skill → 下次按需加载。这一步我们缺。

### 3. 信任是"共同建构"的，不是静态的
Claude Code auto-approve 率从 <50 会话的 ~20% 涨到 750 会话的 >40%。说明信任边界是随轨迹演化的。我们的 P0-P3 是静态矩阵。
⚠️ 但让边界自适应 = 安全相关变更，触碰红线边缘，属 P1，必须 Daryl 拍板。本轮只点出这是前沿方向，不建议现在动。

## 四、诚实的能力差距盘点（对照我们自己的 AGENTS.md 全貌）

已对齐 ✅：AGENTS.md 指令层 / SKILL.md / 子代理 / Sentinel before_tool_call（论文反而印证了逐动作方向）/ cron 审计。

真正缺的（按价值排序）：
1. **巩固引擎**（Dreams 等价物）：从"验证"升级到"语义压缩"
2. **自动维护的封顶索引**：MEMORY.md 从"纯指令库"升级为"指令 + 压缩后的情景摘要"
3. **lesson→skill 闭环**：让教训变成能力，而非死文档
4. （可选，P1）信任自适应边界：前沿但触红线

## 五、具体提案：OpenClaw "Dream Engine"

- **触发**：heartbeat 检测空闲 N 分钟 + 每日 23:59 兜底（不再单点）
- **输入**：近期 daily logs + session transcripts + episodes + active_tasks + failure_patterns.json
- **输出**（全部写 staging，不碰原文件）：
  - (a) 重建的封顶索引 `memory/INDEX_auto.md`（≤200 行，指令+压缩摘要）
  - (b) 去重/调和后的 episodes
  - (c) 候选 skill（从重复出现的教训中蒸馏）
- **审阅**：人看 diff，确认后应用（对齐 Dreams 的"输入库不变、输出可丢弃"）
- **成本**：默认 flash 模型，pro 仅确认阶段用；每日 ≤N 次；纯本地不调 LLM 的部分优先（对齐成本护栏）
- **决策点**：P1（架构方向），需 Daryl 确认里程碑+验收标准后再动工

> 红线自查：本提案只动记忆层 + 技能层，不碰 system prompt/safety 规则；巩固输出需人审阅后才生效。
