# 长线任务运行规范（Long-horizon Task Protocol）

> 背景：我们用的模型上下文窗口有限（DeepSeek 系列约 128K，且 compaction 后细节衰减）。
> 对策不是"要更大的窗口"，而是**把上下文从"对话内存"迁移到"磁盘状态机 + 检索"**。
> 规则：任何预计 >10 步 / 跨 session / 跨天的任务，必须走本协议。

## 一、五个基本杠杆

| 杠杆 | 解决什么 | 我们的落地做法 |
|------|---------|---------------|
| ① 外部化状态 | 模型忘了，磁盘不忘 | `scripts/longtask.sh` + `memory/longtask/<slug>.md` |
| ② 上下文收敛 | 一次只装"当前一步" | 每回合只读 state 的当前 Step + 最近 2 条日志 |
| ③ 检索代替装载 | 不把全历史塞进 prompt | `memory_search` / `memory_get` / `rg` 按需取片段 |
| ④ 分工与隔离 | 脏活不污染主上下文 | `sessions_spawn` 子 Agent（隔离上下文），只回收结论 |
| ⑤ 机械断点 | 上下文断掉也能续 | 每步结束必须落盘：产物路径、校验结果、下一步 |

## 二、标准工作循环（每个回合只做这些）

```
1. ./scripts/longtask.sh status <slug>      # 看当前 Step
2. 只读该 Step 需要的文件/数据（禁止全量读日志）
3. 干活 → 产物写入固定路径（不是留在会话里）
4. ./scripts/longtask.sh log <slug> "产物: <路径> | 校验: <结果>"
5. ./scripts/longtask.sh done <slug> "一句结论"
6. 若下一步是新方向 → add 新步骤再回到 1
```

## 三、任务拆分原则

- **一步一可验证产物**：每步结束必须有能 `ls` 出来的东西（文件/记录/截图/日志）
- **单步 ≤ 一次 context 窗口的 1/4**：超了就再拆
- **无状态步骤可并行**：用子 Agent 并行跑，主 session 只收摘要
- **有状态主线不并行**：串行，靠 longtask state 传递

## 四、context 快满时的正确动作（不要硬撑）

1. 先落盘：未写的中间结果立刻写文件
2. `longtask.sh log` 记下"已到哪、下一步干什么、哪些路径重要"
3. 允许 compaction 发生（OpenClaw 会在 compaction 前提醒落盘）
4. 恢复时：只读 longtask state + memory/当日日记，不要回溯全对话

## 五、什么情况该换工具（而不是硬编上下文）

| 场景 | 建议 |
|------|------|
| 大量重复机械处理（批转文档、批量翻译） | 写成脚本，Agent 只调度不逐条推理 |
| 需要全量比对的超长文档 | 先切块建索引（脚本），再检索比对 |
| 需要长时间无人值守 | `cron` 定时任务，每轮无状态、状态落盘 |
| 需要保住"每一句原文" | 考虑安装 `lossless-claw` context engine 插件（不丢历史，检索式回填） |

## 六、验收标准（自检）

- [ ] 中断后新 session 只看 longtask state 能继续干
- [ ] 每步有产物路径，别人（或未来的我）能接管
- [ ] 主 session 上下文没被中间产物撑爆
