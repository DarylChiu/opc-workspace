## 一、自诊断：前两次需求对齐为什么没真正对齐？

**结论：第一次问错了层级（全是实现层，没有产品层）；第二次理解偏了（把「极简前端」做成了「结果展示」，而不是「可用工作台」）；三次之间范围持续自我膨胀。**

### 第一次对齐（7/19 · 变现加速器定位）——对齐的是「产品是什么」，不是「用户怎么用」
当时确认的内容（project_xiaofeng.md 关键决策表）：16:9+9:16 双格式、BGM 驱动编排、三层情感漏斗。**全部是引擎架构/输出规格**——我确认了"这个产品干什么"，没确认"打开这个产品的人第一步做什么、每一步要做什么决定"。更糟的是：定位确认后我直接扎进 Phase 0 引擎开发（14 个模块，CLI 驱动），把"人怎么用"这个最大的未知数完全押后，等到 7/23 才第一次碰前端。

### 第二次对齐（7/23 · 极简可视化前端）——当天 rush 交付，理解偏了 + 交互设计深度不够
Daryl 要"极简可视化前端"，我当天的交付物是 **5 个节点的一键跑批 + 结果卡片展示**，还带了一堆 bug，Daryl 原话："根本用不了，算了，你把今天整个项目的内容都发给Kitty让她来做Debuger，太多Bug了"（HANDOFF_TO_KITTY.md 有完整记录）。

这里有两个致命问题（**8/5 Daryl 纠正后的归因**）：
1. **Grill-me 里交互逻辑问题问得太少、深度不够**——不是"设计稿未确认"：设计稿走过 Grill-me 需求核对，Daryl 当时提醒我 5 个问题不够，我补到 7 个，开发计划中的设计他也确认过。真正的失误是：交互逻辑层面的问题（用户怎么操作、操作后发生什么）问得又少又浅，是被 Daryl 提醒才补问的。
2. **v3.0 实现时把已确认的设计自我简化成了展示**：设计稿承诺的拖拽、滑条、编辑、缩略图预览，实现时全部砍掉，退化成"按钮 + 结果卡片"。

### 第三次（7/31 · 01-素材扫描 4 项需求）——把产品逻辑问题当成格式偏好问题抛给用户
Daryl 终于开始逐模块喂交互需求（这正是他对我 v3.0 不满的信号）。（**8/5 Daryl 纠正后的归因**：他其实回复了，日期格式也确认了，不是"没回复阻塞"。）真正的问题是：**我把一个产品逻辑问题当成了格式偏好问题**——用户看到的文件名是乱码（`VID_20260507_151812_00_185` → `151812_00_185`，看不出是哪天的第几条、内容是什么），无法对号入座，所以"日期格式"根本不是格式选择，而是"文件名必须可读/可改"的需求。这种从用户视角就能推演出来的逻辑问题，应该我自己定方案（文件名映射/可读化/可重命名），而不是让用户在几个格式里选。

> Daryl 定性：这是作为开发 Agent 需要沉淀的「用户思维」开发习惯。

## 二、机制层面：开发机制缺了什么？

| 缺口 | 具体表现 | 后果 |
|------|---------|------|
| **没有需求分层** | 从没区分"产品层需求（用户场景/操作流/决策点）"和"实现层需求（技术选型/数据结构）" | 第一次对齐全在实现层，产品层从未被问过 |
| **没有原型/线框先行** | 确认的是文字定位，不是界面；设计稿是 ASCII 图，没转成可确认的线框 | 双方对"前端长什么样"的理解完全不同 |
| **里程碑验收标准模糊** | "5 节点全可视化"——"可视化"没定义到交互程度 | 我交付"能看结果"就以为达标，Daryl 要的是"能用" |
| **没有默认方案机制** | 总是抛开放式问题（"哪些节点需要可视化？"、"根目录范围？"）；甚至把**产品逻辑问题当格式偏好问**（文件名乱码→该自己定可读化/可重命名方案，却问用户选哪个格式） | 用户要替我做本应我做的产品决策；8/5 Daryl 纠正：这是「用户思维」开发习惯缺失 |
| **质量门禁只管 bug 不管产品符合度** | 7/23 后落地了 L5 e2e 自检，但只查"能不能跑通" | "能跑"和"是用户要的"是两回事，bug 少了但方向错了 |
| **范围自我膨胀** | 引擎 14 模块、设计稿 v1.0→v2.0 自己 +10h 功能（降调降速/情绪素材库） | 越做越大，核心交互问题越拖越后 |

## 三、如果重来：第一次需求我应该问的问题清单（产品层）

1. **用户旅程**：你拿到这个工具，从素材到成片，完整走一遍是什么样的？（5 分钟讲完，这是最重要的一个问题）
2. **首屏**：打开工具第一屏应该看到什么？先选素材还是先选歌？
3. **决策点**：整个流程里，哪些环节你必须亲自拍板？哪些全自动就行？（比如：素材取舍？BGM 段落分配？预览后改哪里？）
4. **交互范式**（最致命的一问）：你要的是「自动生成 + 最后微调」的自动化工具，还是「自己上手编排 + AI 辅助」的编辑器？——**这两个的前端交互完全不同，我这次就是栽在这**：我按前者做了展示，你可能要的是后者。
5. **不满意的表达**：自动结果不合意时，你想怎么改？点选替换？拖拽？重新生成？还是改参数再跑？
6. **素材/歌的浏览**：卡片网格？列表？时间线？需要预览播放吗？
8. **素材识别（用户思维新增）**：用户看到一堆 `VID_20260507_151812_00_185.mp4` 时，怎么认出"这是哪天哪条、内容是什么"？——文件名乱码→需要可读化/可重命名/内容标签，这种问题**不该问用户，该自己推演后给方案**
7. **验收操作**：你会怎么验证它好不好用？——请描述你拿到手后的前 5 分钟操作（这比任何需求文档都准）。

## 四、v3.0 前端交互缺陷（实测数据，非感觉）

对 frontend/index.html 做了能力盘点：

| 能力 | 设计稿承诺 | v3.0 实测 |
|------|-----------|----------|
| 拖拽（素材排序/替换/入候选池） | ✅ 多处 | **0 个拖拽事件** |
| 滑条（降调降速） | ✅ | **0 个 range 输入** |
| 编辑（对白修改/场景边界/情绪标签） | ✅ | **0 个 contenteditable** |
| 缩略图 + 悬停预览 | ✅ | **0 张缩略图**（emoji 占位） |
| 交互形态 | 工作台 | **16 个按钮的"跑批-看结果"仪表盘** |

具体缺陷（站在"用户会怎么用"角度）：
- **素材扫描不可选**：日期硬编码在代码里，用户没法勾选要处理的素材（今天修的"只检测前3个"也是同类问题——硬编码 `Math.min(files.length,3)`）
- **没有预览能力**：全程看不到视频画面/听不到音频片段，只能看文字结果——剪辑工具不能预览等于盲剪
- **决策点没有 UI**：流程设计里有「预览→通过/调整/重来」这个唯一人工决策点，前端只有个「导出」按钮
- **步骤状态断裂**：ASR 视图硬编码 date=20260430 跟素材扫描视图不一致（今天刚修的 bug 就是证据）——步骤间不共享用户的选择
- **长任务无进度/取消/断点**：ASR/情感分析转圈到底，没有每项进度、没有取消、失败不能单独重试

**一句话总结：我把"极简"理解成了"简单展示"，Daryl 的"极简"是"极简但能用、交互要顺手"。后端是引擎，前端才是产品——我花在引擎上的心思远多于花在"人怎么用"上的心思。**

## 五、需要什么支持来避免第四次澄清？

1. **Daryl**：
   - 每个模块需求附 **1-2 句"我会怎么用"**（用户故事），不用写完整 PRD，一句话就够我抓到产品意图
   - 我提交交互方案（线框+交互清单，30 分钟产出）后，**24h 内 approve / reject 即可，不回默认同意**——不要再让开放问题阻塞
2. **机制（请 Kitty 在 OPC 看板配合）**：
   - 在 workflow 里把「交互设计确认」设为每个模块开发的**前置强制节点**（未确认 status=blocked，不允许进开发）
   - 需求分级模板：产品层（场景/流程/决策点/验收操作）必须 Daryl 确认后才能进入实现层
3. **我自己**：
   - 每个模块先出 ASCII 线框 + 交互清单再写代码，不自作主张加功能
   - 所有问题给默认方案+选项，不再抛开放式问题
   - 交付出前用「Daryl 的前 5 分钟操作」走查一遍，而不是只跑技术 e2e
