## 二、整体布局

```
┌──────────────────────────────────────────────────────────────┐
│  TOPBAR · 项目名 + 状态指示 + 一键生成按钮                      │
├──────────┬───────────────────────────────────────────────────┤
│ SIDEBAR  │  ┌─────────────────────────────────────────────┐  │
│ (56→180) │  │  PIPELINE STEPS · 横向流程导航               │  │
│          │  │  [0.2扫描]→[0.4BGM]→[0.5ASR]→[0.6情感]→[0.7匹配] │
│          │  ├─────────────────────────────────────────────┤  │
│          │  │                                             │  │
│          │  │  当前步骤详情区 (占主区域 70%)                 │  │
│          │  │  · 0.2 = 缩略图网格                          │  │
│          │  │  · 0.4 = 歌曲库 / 乐句库 / 波形+段落 / 降调降速│  │
│          │  │  · 0.5 = 对白时间轴+场景标记                  │  │
│          │  │  · 0.6 = 素材情绪卡片 + 情绪素材库             │  │
│          │  │  · 0.7 = 双轨时间线 ★核心决策视图              │  │
│          │  │                                             │  │
│          │  ├─────────────────────────────────────────────┤  │
│          │  │  底部操作栏 · [确认本步] [跳过] [返回上步]      │  │
│          │  └─────────────────────────────────────────────┘  │
└──────────┴───────────────────────────────────────────────────┘
```

**核心原则：**
- 横排 Pipeline Steps 作为顶层导航，当前步骤高亮
- 右侧主区域展示当前步骤的**可视化结果 + 编辑能力**
- 每个步骤确认后再推进下一步（也可跳过，保留自动结果）
- **不做时间轴拖拽编辑器**，不做轨道式编辑

```
│ tags (JSON array)    │     │ emotion_tags (JSON)       │
│ created_at           │     │ pitch_shift (半音)        │
│                      │     │ tempo_scale (倍率)        │
│                      │     │ waveform_data (JSON)     │

└─────────────────────┘     └──────────────────────────┘

存储: SQLite, 每首歌 ~20KB(元数据) + ~200KB(波形JSON) + 原始音频(已有)
```

**代价评估：**
- 数据库：SQLite 两张表，纯本地，零 API 成本
- 首次导入：人工或批量导入 5-10 首歌，每首分析 3-5 秒（librosa 本地）
- 后续使用：从库中选歌即可，跳过重复分析
- 乐句库自动生成：BGM 分析时自动拆分并入库乐句，用户也可手动标注
- **开发增量：+3h（数据库 schema + API 端点 + 前端浏览 UI）**

```
│  │ 🔥 Climax(42-55s) G maj ▸ C maj  [🔽降5半音] │ 184 BPM │   │
│  └────────────────────────────────────────────────────────┘   │
│                                                              │
│  💡 降调：降低音高使BGM更柔和，适合 Vlog 叙事                   │
│  💡 升调：提高音高增加紧张感，适合 Build/Climax 段              │
│  💡 变速：放慢增加舒缓感，加快增加节奏感                         │
│                                                              │
│  [🔊 试听调节后效果]  [💾 保存为新版本]  [↺ 恢复原始]           │
└──────────────────────────────────────────────────────────────┘
```

**技术实现：**

| 功能 | 工具 | 命令示例 | API 成本 |
|------|------|---------|:---:|
| 降调/升调 | ffmpeg rubberband | `ffmpeg -i in.mp3 -af "rubberband=pitch=1.0595^(半音数)" out.mp3` | $0 |
| 变速 | ffmpeg atempo | `ffmpeg -i in.mp3 -af "atempo=倍率" out.mp3` | $0 |
| 降调+变速 | ffmpeg rubberband | `ffmpeg -i in.mp3 -af "rubberband=pitch=比率:tempo=比率" out.mp3` | $0 |
| 乐句提取 | ffmpeg 裁剪 | `ffmpeg -i in.mp3 -ss 起始 -t 时长 out.mp3` | $0 |

> 全部纯本地 ffmpeg 操作，零 API 成本。rubberband 是 ffmpeg 内置高质量音高/速度变换滤镜。

**代价评估：**
- 纯本地 ffmpeg，零 API 成本
- 乐句级调节：需要先提取片段 → 分别处理 → 合并
- 实时试听：生成临时 mp3 片段，前端 `<audio>` 播放
- **开发增量：+2h（前后端音频调节管线 + UI 滑条 + 试听）**

### 0.6 · EMOTION FUNNEL — 情感分析 ★v2.0 重构

> v2.0 核心变更：
> - **默认 L2+L3 策略**（撇脂理念，质量优先，不再提供 L1-only 模式）
> - **新增情绪数据素材库**（已筛选片段可跨项目复用）
> - L1 DeepSeek 对白情感保留，作为内部粗筛信号，用户不可见/不可干预

#### 0.6a · 策略调整背景

**v1.0 问题：** 提供了 L1-only / L1+L2 / L2+L3 等多种分析深度选项，导致：
- 用户需要决策「用哪层」——增加了认知负担
- L2/L3 不完整的片段在 Matcher 匹配时质量下降
- 121.mp4 中「白建筑+海面+飞鸟」只有原生视频分析才能准确捕捉（帧级分析容易漏掉帧间掠过的小元素）

**v2.0 策略（撇脂理念）：**

```
┌────────────────────────────────────────────────────┐
│              情感漏斗 v2.0 · 撇脂策略               │
│                                                    │
│  L1 · DeepSeek 对白情感                             │
│  ├─ 系统内部粗筛（不可见）                           │
│  └─ 输入: ASR 文本 → 输出: 对白情绪信号              │
│                                                    │
│  L2 · 视觉信号精筛                                  │
│  ├─ 颜色直方图 + 亮度曲线 + 运动矢量                 │
│  ├─ 高频采样（每 0.5s 一帧）                        │
│  └─ 输入: 视频帧 → 输出: 视觉情绪刻面                │
│                                                    │
│  L3 · Gemini 原生视频分析 ⭐ 默认开启，不可跳过       │
│  ├─ 发送视频片段本身（非静态帧）                     │
│  ├─ 理解运动、转场、构图变化                         │
│  ├─ 输出: 完整情感画像 + 场景元素 + 叙事角色          │
│  └─ 这是找到「白建筑+海面+飞鸟」的关键层             │
│                                                    │
│  所有片段强制走完 L1→L2→L3，用户无需选择             │
└────────────────────────────────────────────────────┘
```

**情绪数据素材库设计：**

```
┌───────────────────────────┐
│ 情绪素材库 emotion_lib     │
├───────────────────────────┤
│ id (PK)                   │
│ source_file               │  ← 原始文件路径
│ time_start / time_end     │  ← 片段起止时间
│ thumbnail_path            │  ← 缩略图
│ emotion_primary           │  ← 主要情绪标签
│ emotion_secondary (JSON)  │  ← 次要情绪+分数
│ scene_elements (JSON)     │  ← L3 识别的场景元素
│ visual_tags (JSON)        │  ← 视觉标签 (海/建筑/鸟/日落/...)
│ confidence_l3             │  ← L3 置信度
│ project_source            │  ← 来源项目 (可追溯)
│ is_starred                │  ← 是否加精
│ usage_count               │  ← 被复用次数
│ created_at                │
└───────────────────────────┘

存储: SQLite, 每片段 ~2KB(元数据) + ~50KB(缩略图)
搜索: 按 emotion_primary / visual_tags / scene_elements 多维过滤
复用: Matcher 候选池可混入「素材库」的已筛选片段
```

## 四、技术方案

### 架构更新

```
Frontend (index.html)
  └─ OPC Design System v1.0 CSS
  └─ Vanilla JS (零框架依赖)
  └─ 对接 Engine API Server (FastAPI)
       ├─ POST /scan              → 扫描素材
       ├─ POST /bgm/analyze       → BGM 解析 + 自动入库
       ├─ GET  /bgm/library        → 歌曲库列表
       ├─ GET  /bgm/library/:id    → 歌曲详情 + 乐句
       ├─ POST /bgm/library/import → 导入新歌
       ├─ POST /bgm/shift          → 降调降速处理
       ├─ POST /video/analyze      → ASR+场景+情感(L1→L2→L3强制全量)
       ├─ GET  /emotion/library    → 情绪素材库
       ├─ POST /emotion/library    → 片段入库
       ├─ POST /edit/create        → 匹配编排
       └─ POST /render/preview     → 预览渲染
```

### 文件结构
```
video_editor_mvp/
  ├─ frontend/
  │   └─ index.html              ← 单文件应用 (~2000行)
  ├─ data/
  │   ├─ song_library.db         ← 歌曲库 + 乐句库 (SQLite)
  │   └─ emotion_library.db      ← 情绪素材库 (SQLite)
  └─ (静态资源内联)
```
